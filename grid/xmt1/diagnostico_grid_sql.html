Diagnóstico grid_sql / BigQuery

App aislada de una sola pantalla, solo para probar el ciclo Dataset Definition (grid_sql) → refresh → contenido, paso por paso, mostrando la respuesta cruda de Grid en cada llamada. Sirve para distinguir si un fallo (ej. el 422 "refresh_mode: Input should be 'external'" visto en Premissort) es específico de un documento/dataset, o un cambio general de la plataforma — probando contra el MISMO doc_id que ya falla y, si hace falta, contra uno distinto. No guarda nada permanente: cada "Ejecutar" solo pisa el dataset de prueba indicado abajo.

Paso 1 — GET definición
Lee la Dataset Definition actual (o 404 si nunca se creó).
Paso 2 — POST/PATCH definición
Crea o actualiza la definición con el SQL y refresh_mode de arriba. Aquí es donde Premissort recibió el 422.
Paso 3 — POST refresh
Dispara la ejecución. Requiere rol editor sobre el documento (viewer recibe 403).
Paso 4 — GET contenido
Lee el contenido materializado del dataset.
