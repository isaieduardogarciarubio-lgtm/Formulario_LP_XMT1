Diagnóstico Sheets — Grid

Prueba el proxy de Google Sheets que ya conectaste en Grid (OAuth por documento). El parámetro doc_id resuelve el token OAuth del DUEÑO del documento — cualquiera que pueda llamar este endpoint para ese doc_id lee la sheet montado en tu conexión, no necesita conectar su propia cuenta de Google. No hay límite propio documentado para /sheets, así que el paso 4 mide empíricamente qué tan seguido se puede recargar antes de un 429/error.

Paso 1 — Metadata de la sheet
Confirma que Grid puede resolver la sheet con tu conexión — trae nombres de tabs, dimensiones, etc.
Paso 2 — Leer valores
Trae los valores del rango indicado arriba — así se vería lo que consumiría captura_auditoria.html.
Paso 3 — Escribir un valor de prueba (opcional, modifica la sheet real)
Escribe la fecha/hora actual en la celda que pongas, para confirmar que el flujo de escritura también funciona (útil si algún día quieres escribir resultados de vuelta, no solo leer). Sáltate este paso si no quieres tocar la sheet real.
Paso 4 — Medir qué tan seguido se puede recargar
Dispara N lecturas consecutivas (GET valores) con el intervalo que indiques, y marca la primera que falle (429 u otro error) — así sabemos el límite real en vez de adivinar entre el límite general de Grid (60 req/min documentado para datasets) y la cuota de la Google Sheets API detrás de tu token.
